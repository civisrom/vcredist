# Runtimes AIO для Windows 10/11

Форк [abbodi1406/vcredist](https://github.com/abbodi1406/vcredist), который собирает общий офлайн-установщик библиотек Visual C++, Visual Basic и .NET Windows Desktop Runtime для x86/x64.

Проект использует готовые библиотеки Microsoft. Visual C++ и VSTO перепаковываются в компактные MSI с общим сжатым архивом. Для .NET сохраняются оригинальные подписанные EXE Microsoft: они управляют общими компонентами `dotnet`, восстановлением и удалением. Поэтому размер полного набора в основном определяется пакетами .NET.

## Состав

| Компонент | Что включается |
| --- | --- |
| Visual C++ 2005 | 8.0.50727.6229, x86/x64 |
| Visual C++ 2008 | 9.0.30729.7523, x86/x64 |
| Visual C++ 2010 | 10.0.40219.473, x86/x64 |
| Visual C++ 2012 | 11.0.61135.400, x86/x64 |
| Visual C++ 2013 | 12.0.40664.0, x86/x64 |
| Visual C++ v14 | Последний выпуск Microsoft для семейства 2015 и новее, x86/x64 |
| Visual Studio 2010 Tools for Office Runtime | Актуальный установщик Microsoft; выбирается архитектура Windows |
| Старые Visual Basic / Visual C++ | VB Runtime и Visual C++ 2002/2003, x86 |
| .NET Windows Desktop Runtime | Последний патч каждой стабильной ветки начиная с 6.0, x86/x64 |

Windows Desktop Runtime включает обычный .NET Runtime и библиотеки WPF/WinForms. Ветки 6, 7, 8, 9 и 10 устанавливаются рядом. Новые стабильные ветки добавляются по официальному каталогу Microsoft; preview и RC исключаются. Ветки сохраняются после завершения поддержки, поэтому для .NET 6/7 доступны последние выпущенные патчи, без новых обновлений безопасности. [Политика поддержки Microsoft](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).

UCRT используется из состава Windows 10/11. Сборка предназначена для x86/x64; ARM64 не включён. Требования отдельных выпусков к версии Windows определяются Microsoft. [Требования .NET](https://learn.microsoft.com/en-us/dotnet/core/install/windows).

Точные версии, источники, коды MSI и контрольные суммы каждого выпуска находятся в его `manifest.json`. Версия MSI может отличаться от версии DLL в таблице выше.

## Скачать и установить

Откройте [последний релиз](https://github.com/civisrom/vcredist/releases/latest). Каждый выпуск содержит:

- `Runtimes_AIO_x86_x64.exe` — полный офлайн-установщик;
- `manifest.json` — состав и происхождение файлов;
- `SHA256SUMS` — контрольную сумму EXE.

Файлы релиза доступны без входа в GitHub. Дополнительно проверенный пакет хранится 90 дней в артефактах [GitHub Actions](https://github.com/civisrom/vcredist/actions/workflows/update.yml), где для скачивания нужен вход. Временные артефакты `unverified-…` предназначены для тестовых машин и удаляются после проверки.

Запустите EXE от имени администратора. Интернет на компьютере, где устанавливается пакет, не требуется.

| Параметры EXE | Действие |
| --- | --- |
| Без параметров или `/y` | Окно выбора библиотек; первоначально отмечен весь набор |
| `/ai /gm2` | Тихая установка всего набора, включая скрытую распаковку |
| `/ai1 /gm2` | Обновление уже установленных семейств |
| `/aiF /gm2` | Восстановление установленных и добавление отсутствующих компонентов |
| `/aiD /gm2` | Проверка файлов и состава без установки; окно показывает, что будет установлено, обновлено или оставлено без изменений |
| `/?` | Справка |

Установленные старые версии обновляются внутри своего семейства, совпадающие и более новые пропускаются без запуска их установщиков. Поколения Visual C++ и ветки .NET сохраняются рядом. Для Visual C++ 2010 сравниваются версии системных DLL: патчи `.325` и `.473` имеют одинаковую версию MSI `10.0.40219`, поэтому одной проверки регистрации MSI недостаточно. Перед любым изменением системы проверяются SHA256 всех файлов пакета. Перезагрузка автоматически не выполняется.

Если библиотека раньше была установлена оригинальным EXE Microsoft, после обновления его запись в списке программ показывала бы старую версию и не давала бы удалить новые MSI. Такая запись удаляется штатной командой самого установщика Microsoft, но только когда все его пакеты уже заменены более новыми из этого набора; записи совпадающих версий и других программ сохраняются. Удалённые записи перечисляются в отчёте.

Восстановление возвращает отсутствующие файлы, а для Visual C++ 2010 и новее и старых VB/C также перезаписывает файл той же версии с изменённым содержимым. Для Visual C++ 2010, если обновление не подтвердилось из-за стороннего зарегистрированного патча, патчи этого продукта снимаются и установка повторяется один раз.

Перед установкой SFX распаковывает пакет во временную подпапку `%TEMP%` текущего пользователя — обычно `C:\Users\<имя>\AppData\Local\Temp\`. После закрытия установщика эта подпапка удаляется. Собственные системные кэши Windows Installer и оригинальных установщиков .NET могут сохраняться для восстановления и удаления компонентов.

Окна распаковки и справки рассчитывают размеры по содержимому и системному шрифту Windows. В окнах выбора, установки и результата длинный текст переносится; для списков и подробных пояснений доступна прокрутка.

Для диагностики и автоматизации распакуйте EXE с помощью 7-Zip и выполните из открытого командного окна:

```bat
Installer.cmd -Mode check
Installer.cmd -Mode check -ShowPlan
Installer.cmd -SelectPackages
Installer.cmd -Quiet
Installer.cmd -Components "vc14,dotnet-8.0" -Quiet
Installer.cmd -Mode repair -Quiet
```

В окне можно выбрать отдельные поколения Visual C++ и ветки .NET. Рядом с каждым компонентом показано его состояние: не установлено, доступно обновление или обновление не требуется. Кнопки «Выбрать всё» и «Снять выбор» меняют отметки; «Отмена» закрывает окно без установки. На Windows x64 выбранные семейства устанавливаются в вариантах x86 и x64, а для VSTO используется архитектура системы. Уже установленные невыбранные библиотеки сохраняются.

Параметр `-Components` принимает идентификаторы через запятую:

| Идентификатор | Компонент |
| --- | --- |
| `vc2005`, `vc2008`, `vc2010`, `vc2012`, `vc2013` | Соответствующее поколение Visual C++ |
| `vc14` | Актуальный Visual C++ v14 |
| `vbc` | Старые Visual Basic / Visual C++ 2002–2003 |
| `vstor` | Visual Studio Tools for Office Runtime |
| `dotnet-6.0`, `dotnet-7.0`, `dotnet-8.0`, `dotnet-9.0`, `dotnet-10.0` | Указанная ветка Windows Desktop Runtime |

Новые стабильные ветки получают идентификатор `dotnet-<ветка>` и автоматически появляются в окне. Неизвестный идентификатор останавливает установку до изменения системы. `-Components` также работает с `-Mode update` и `-Mode repair`.

`Installer.cmd` возвращает `0` при успехе, `3010` при необходимости перезагрузки и `1` при ошибке. Если сценарий не удалось запустить вовсе (например, из-за политики выполнения PowerShell), при обычном запуске показывается сообщение; с `-Quiet` и в консольном `-Mode check` окна не открываются. `Install.ps1` нужно запускать 64-разрядным PowerShell — `Installer.cmd` выбирает его сам. SFX-оболочка не передаёт код завершения вложенного скрипта: для контроля результата автоматического развёртывания используйте распакованный `Installer.cmd` и журналы.

После обычной установки открывается окно результата: компонент, архитектура, версия в пакете, версии до и после, результат обработки. Причина показана под таблицей для выбранной строки; при ошибке окно открывается на компоненте, на котором она произошла. Отдельно отмечаются установленные, обновлённые, восстановленные, пропущенные и невыбранные компоненты, ошибки и операции, которые не выполнялись. При ошибке сохраняются результаты уже обработанных пакетов.

Для каждого запуска создаётся отдельная папка в `%ProgramData%\civisrom\VisualCppRedist\logs` с журналами, читаемым `report.txt` и машинным `report.json`. Кнопки «Открыть отчёт» и «Открыть журналы» доступны в итоговом окне. Режим `-Quiet` сохраняет отчёты без окон, а `-Mode check` только проверяет пакет и выводит план действий в консоль.

Если установщик Microsoft вернул код `3010`, итоговое окно сообщает о необходимости перезагрузки. Если новая версия ещё не видна, компонент получает статус «Ожидает перезагрузки», а в графе «После» остаётся фактически обнаруженная версия. После перезагрузки повторный запуск проверит результат и пропустит совпадающие версии. [Почему Windows Installer требует перезагрузку](https://learn.microsoft.com/en-us/windows/win32/msi/system-reboots).

Для удаления отдельных компонентов используйте список установленных программ Windows. Если MSI остаётся установленным, от него зависит другая программа, например Visual Studio или запись EXE Microsoft той же версии. Общие компоненты .NET, которые нужны другим пакетам или SDK, могут остаться установленными.

## Автоматическое обновление

Workflow [update.yml](.github/workflows/update.yml) выполняет проверку первого числа каждого месяца в **06:23 UTC**. GitHub может задерживать запуск расписания. Дополнительно доступны ручной запуск **Run workflow** и сборка после изменения скриптов.

Проверяются постоянные ссылки Microsoft для VC++ v14, страница загрузки VSTO и официальный каталог выпусков .NET. Изменение промежуточного патча тоже учитывается. Если проверенный пакет с теми же исходными файлами и скриптами уже существует, повторная сборка пропускается. Параметр **force_build** позволяет собрать его заново.

Год в названии Visual Studio не ограничивает обновления v14: следующий выпуск по той же постоянной ссылке тоже будет обработан. Новые стабильные ветки .NET обнаруживаются автоматически, включая первый выпуск `.0`, у которого ещё нет предыдущего стабильного патча для проверки обновления. Совершенно новое семейство Visual C++, изменение формата установщиков, отсутствие x86 или отказ от поддержки Windows 10 могут потребовать изменения рецепта. В этих случаях проверки остановят публикацию.

Новый артефакт становится готовым только после прохождения всех четырёх тестовых стендов. Из ветки `master` затем автоматически создаётся GitHub Release с кратким русским описанием версий и проверок. Тег `runtimes-…` определяется составом и рецептом сборки; одинаковый выпуск повторно не публикуется. Если публикация прервалась, следующий запуск продолжит её с уже проверенным артефактом. Перед открытием релиза проверяются SHA256 загруженных файлов.

При ошибке загрузки, подписи, контрольной суммы или тестов сборка не публикуется как проверенная. Бинарные файлы не добавляются в Git. Используются штатный `GITHUB_TOKEN` и Actions на Node.js 24, закреплённые по SHA.

Отдельный шаг поддерживает расписание активным через API GitHub, без фиктивных коммитов.

## Источники и старые библиотеки

Каталог источников находится в [automation/sources.json](automation/sources.json). Современные VC++, VSTO и .NET загружаются с серверов Microsoft. Для .NET проверяются SHA512 из официальных метаданных и подпись Microsoft; для актуальных VC++ и VSTO — подпись Microsoft. Перед установкой дополнительно проверяются SHA256 файлов готового пакета.

Для старых VC++ 2005–2013 и VB/C используется зафиксированный выпуск [abbodi1406 v0.105.0](https://github.com/abbodi1406/vcredist/releases/tag/v0.105.0), проверяемый по SHA256. Для этих компонентов сохраняется проверенный набор upstream: обычные публичные загрузки Microsoft не всегда содержат те же поздние исправления. Автоматическое перепаковывание старых веток из других исходников в этом рецепте не выполняется.

Публичные старые установщики Microsoft также проверяются по контрольным суммам. Если они изменятся, сборка остановится до проверки и обновления рецепта старых пакетов. Изменение одного SHA256 без проверки содержимого не считается обновлением рецепта.

Собранный EXE является самостоятельным репаком и не подписан сертификатом Microsoft. Подписи оригинальных .NET EXE сохраняются; изменённые MSI Visual C++ не сохраняют исходную подпись контейнера.

## Проверки

Обязательная матрица состоит из четырёх отдельных временных машин:

| Система x64 | Среда | После перезагрузки |
| --- | --- | --- |
| Windows 10 Enterprise Evaluation 22H2, сборка 19045 | Чистая виртуальная машина | Проверка библиотек, приложений и повторный запуск интерфейса установщика |
| Windows 11 Enterprise Evaluation 25H2, сборка 26200 | Чистая виртуальная машина | Проверка библиотек, приложений и повторный запуск интерфейса установщика |
| Windows Server 2022 | GitHub-hosted runner | Нет |
| Windows Server 2025 | GitHub-hosted runner | Нет |

На каждом стенде выполняются:

- проверка настоящего окна выбора: отмена, выбор всех компонентов, снятие отметок и выбор одного семейства;
- установка настоящего SFX-установщика, повторная установка и проверка регистрации пакетов;
- обновление реально установленного предыдущего патча .NET;
- восстановление намеренно удалённых файлов Visual C++ и Windows Desktop Runtime;
- запуск приложений WPF/WinForms на каждой ветке .NET, отдельно в x86 и x64, с запрещённым переходом на другой патч;
- загрузка DLL Visual C++ разных поколений, MFC, OpenMP и старых VB/C-библиотек;
- удаление и повторная установка каждой .NET-сборки с запуском приложений на остальных ветках после каждого удаления;
- удаление 20 MSI-компонентов, проверка режима обновления и повторная установка;
- установка только выбранного семейства VC++ с подтверждением, что остальные удалённые MSI не появились снова;
- восстановление выбранной ветки .NET в x86/x64 с проверкой, что установщики остальных компонентов не запускались;
- отказ от установки при повреждении пакета и проверка отсутствия попыток понизить установленные версии.

На Windows 10/11 дополнительно подготавливается смешанный набор: старые оригинальные VC++ 2005/2008/2010/2012/v14 и предыдущие патчи всех включённых веток .NET, а также совпадающие и отсутствующие компоненты. Проверяются выборочное обновление и установка всего набора, версии в итоговом отчёте, переход DLL VC++ 2010 с `.325` на `.473`, пропуск совпадающих версий без запуска дочерних установщиков. Затем установщику предлагаются настоящие старые пакеты VC++ v14 и .NET при уже установленных новых версиях: проверка требует пропуска и сохранения работоспособности приложений.

Проверки интерфейса открывают окна выбора, хода установки и результата, включая ошибку и запрос перезагрузки. Размеры шрифта 10, 12,5, 15 и 20 проверяются отдельно; это проверка увеличенного шрифта, а не всех режимов DPI Windows. На клиентских машинах также снимаются реальные этапы SFX: справка, распаковка, подтверждение отмены, проверка файлов, выбор библиотек, установка компонентов и итог. После перезагрузки повторный запуск должен показать пропуск всех совпадающих версий.

Ручной параметр **interface_only** выполняет только проверки логики и окон. Для локального просмотра снимков можно передать публичный PEM-сертификат в **screenshot_certificate**: снимки передаются временным зашифрованным артефактом с хранением один день. Закрытый ключ остаётся у получателя и в Actions не передаётся. Без сертификата снимки остаются на одноразовом стенде; открытые снимки и отчёты не публикуются в репозитории.

Образы GitHub содержат Visual Studio и SDK, в том числе распакованные из ZIP. Перед тестами актуальный x64 SDK регистрируется официальным установщиком Microsoft, чтобы у общих компонентов был зарегистрированный владелец. Если Windows Installer сохраняет MSI из-за зависимостей Visual Studio, тест сначала подтверждает причину по журналу, а затем удаляет этот MSI с `IGNOREDEPENDENCIES=ALL` только на одноразовом стенде. Пользовательский установщик этот параметр не использует.

Клиентские Windows запускаются через KVM на `ubuntu-24.04` с помощью закреплённого образа [dockur/windows](https://github.com/dockur/windows). ISO загружаются непосредственно с серверов Microsoft и проверяются по SHA256. Версии образов и контрольные суммы находятся в [automation/client/images.json](automation/client/images.json), сценарий — в [client-windows.yml](.github/workflows/client-windows.yml). При отсутствии KVM или ошибке загрузки стенд завершается с ошибкой. После полного цикла гостевая Windows действительно перезагружается; тест сверяет время загрузки, регистрацию библиотек и запуск приложений x86/x64.

Логика и совместимость скриптов отдельно проверяются в PowerShell 7 и Windows PowerShell 5.1, включая кодировку русского текста. Разрушающие тесты разрешены только на одноразовых GitHub-hosted runners или специально подготовленных гостевых машинах с проверкой версии ОС и маркера стенда. Журналы тестовых машин не загружаются отдельными артефактами.

Матрица проверяет указанные версии Windows x64 и библиотеки обеих архитектур. Отдельно не проверяются 32-битная Windows, ARM64 и конкретные пользовательские программы. VSTO x86 включён для 32-битной Windows; на этих стендах проверяется VSTO x64. На автоматических стендах UAC отключён; запрос повышения прав в пользовательском сеансе отдельно не проверяется.

## Сборка самостоятельно

Нужны Windows x64, PowerShell 7, 7-Zip, права администратора и доступ в Интернет. Из корня репозитория:

```powershell
./automation/Test.ps1
./automation/Build.ps1 -Force
```

Результат появится в `.build/dist`. Рабочий каталог `.build` перед новой сборкой должен отсутствовать либо укажите новый пустой каталог через `-WorkDirectory`. Скрипт не перезаписывает существующие результаты.

- [abbodi1406](https://github.com/abbodi1406/vcredist) — исходный репак и инструменты подготовки MSI.
- [ricktendo64](https://forums.mydigitallife.net/members/28038/) — VBCRedist_AIO и модифицированные MSI.
- [burfadel](https://forums.mydigitallife.net/members/84828/) — исходный установочный сценарий.
- Microsoft — библиотеки Visual C++, Visual Basic и .NET; названия продуктов принадлежат Microsoft.

Автоматическая сборка, собственный установочный сценарий и тестовые стенды этого форка находятся в `automation/`, `installer/` и `.github/workflows/`.
